# 知識競技場 Knowledge Arena

以 GitHub Pages 與 Firebase Realtime Database 架設的多人即時知識競賽網頁，支援主持人操作、手機掃碼加入、題庫管理及競賽成績匯出。

## 2. 本次更新

V11 新增修正：前台僅選取已儲存雲端題庫及房間設定、返回首頁並保留進度；後台全面 Google 驗證、雲端題庫與修改紀錄、移除建立房間按鈕；預設色票與自訂 HEX；按鈕間距、共用頁首全螢幕、詳細解答箭頭折疊；感謝及個人回顧改版，最終結果及歷史回顧共用三頁籤元件；歷史房間卡片與狀態；控制權三小時及具體錯誤提示。另整合一鍵延長 15 秒、黑色膠囊與寶石藍控制按鈕、作答人數文字及前台網頁內確認／錯誤提示。下列 V10 功能持續保留。

2. 主持人 Google 登入；參賽者使用獨立匿名身分。
3. `editor-preview.html` 歷史房間管理：搜尋、查看排名與題目分析、Excel 匯出、關閉、二次確認刪除。
4. 競賽恢復：首頁與後台雙入口；同帳號可接續未結束且未逾時房間。
5. 主持人回首頁後進入唯讀回顧，沿用最終結果到期時間。
6. 主持人暫停及繼續。
7. 作答延長：每次固定增加 15 秒，可重複點擊累加，無輸入或確認視窗。
8. 作廢當前題目：作答中、解答或即時排名階段均可作廢，撤回該題分數並復原連答、排名與統計；進入下一題或最終結果後不可追溯作廢。

10. 正確選項與詳細解答分區；詳細解答文字及圖片；預設折疊，由主持人同步展開／收合。答案解說新增富文字工具列、文字／圖片混排及解答預覽，並同步呈現在競賽、回顧、歷史管理。
11. 題目答對率及答對、答錯、未答人數。
12. 最終結果第三頁籤「題目分析」。
13. 參賽者個人回顧：自己的答案、正確答案、分數、解說與圖片及篩選。

## 3. 部署與升級

### 3.1 既有網站升級（GitHub V7.0 → V8.0）

**此版不是只上傳 GitHub 就可使用。請在非活動時段操作。**

1. 備份目前 GitHub 檔案、`config.js`、Firebase Realtime Database 資料（Data → Export JSON）、舊安全規則及本機題庫 JSON。不要清除瀏覽器資料。
2. Firebase Console → Authentication → Sign-in method（登入方式）：保留 Anonymous，新增啟用 Google，選擇專案支援電子郵件並儲存。Settings → Authorized domains 確認 `帳號.github.io`（不含路徑）已加入。
3. 先在獨立測試 Firebase 專案／測試頁驗證新版規則與流程。正式升級時停止舊版競賽，將 `database.rules.json` 全文貼入 Realtime Database → Rules 並發布；再上傳新版網頁檔案到原 GitHub Pages 路徑。短暫版本不一致期間舊網頁將無法開房或作答。
4. 保留原 `config.js`，本套件沒有空白替換檔。不要將服務帳戶 JSON、私鑰或管理員憑證放入 GitHub。
5. GitHub Pages 部署後，重新整理各裝置，登入 Google 主持人帳號並建立全新測試房間。依第 9 節完成驗收後才用於活動。
6. 如有問題，備份新增 V11 資料後再評估還原舊版程式及舊規則；不要直接覆蓋整個資料庫。

### 3.2 舊房間遷移

V11 沿用 V10 房間資料結構（state.version 仍為 10），規則拒絕 V9.3 以前房間的參賽者存取及一般主持人修改；舊房間不會因上傳網頁而被實際寫成 closed。舊版匿名 UID 與 Google UID 不同，歷史資料不會自動出現在 Google 帳號下。保留原資料，不自動刪除或轉移所有權。

若要將舊版未關閉房間正式標記為 closed：先匯出 JSON 備份。可在 Firebase Console → Realtime Database → Data 逐一確認 `rooms/<房號>/state`（沒有 `version:10` 的舊房間），將 `stage` 改為 `closed`，將 `allowLateJoin`、`showJoinQR` 改為 false。不要修改 V10 房間或刪除資料。

房間多時可使用套件內 `close-legacy-rooms.mjs`。此為選用的管理員本機工具，不是網頁檔案。需自行取得專案管理權限及 Node.js 18+，在私人工作資料夾安裝 `npm install firebase-admin`，將腳本放入該資料夾。以環境變數 `GOOGLE_APPLICATION_CREDENTIALS` 指向保存在 GitHub 之外的服務帳戶 JSON，`FIREBASE_DATABASE_URL` 設為目標資料庫 URL。先執行 `node close-legacy-rooms.mjs`（只列出候選）；確認備份、網址與候選房號後才執行 `node close-legacy-rooms.mjs --apply`。腳本逐房間交易檢查版本，不刪除成績。無法代替你在真實 Firebase 執行。舊房間是否需重新歸屬 Google 帳號，須另由管理員驗證原擁有者後處理。

### 3.3 首次架設

建立 Firebase 專案與 Web App，複製 `config.example.js` 為 `config.js` 並填入 Web 設定（包括 databaseURL）。啟用 Anonymous 與 Google 登入、建立鎖定模式 Realtime Database、發布本版規則、加入 GitHub Pages 授權網域。將網站檔案上傳 GitHub，啟用 Pages。Firebase Web API key 不等於管理員私鑰；不要公開管理員憑證。

## 4. 系統功能與限制

| 項目 | 規格 |
| --- | --- |
| 參賽者 | 前端最多 50 人；併發加入可能超過，尚未壓力測試 |
| 暱稱 | 最多 100 UTF-16 字元，原有膠囊及換行樣式 |
| 題型 | 單選、是非、排序、圖片辨識 |
| 題數／時間 | 最多 100 題；初始 5–180 秒；每次固定延長 15 秒，可累加 |
| 圖片容量 | 單圖壓縮約 400 KB；題庫文字與內嵌圖片合計上限 2.5 MB（UTF-8），避免房間交易超大。大圖請用 HTTPS 網址 |
| Timeout | 每個期限 0.25–168 小時，逾時即禁止參賽者新存取；資料仍保留 |
| 主持人控制 | 控制權 3 小時、名義續約週期 3 小時（到期前 60 秒安全窗口內續約）；同帳號確認後可接管 |
| 即時作答 | 保留原選項即時暱稱及作答人數（不是嚴格防作弊模式） |
| 最終結果 | 總分、最長連答及題目分析；並列規則維持原版 |
| 音效 | 只限主持人，預設關閉 |

### 房間生命週期

等待加入 → 作答（可暫停／延長）→ 公布解答（可展開）→ 即時排名 → 下一題；最後一題直接最終結果 → 唯讀回顧 → 到期。進行中／暫停中每次主持人操作及到期前背景續約刷新期限；等待加入和最終回顧固定期限不變。最終結果時起算回顧期限，回首頁不重新計時。

逾時由程式及安全規則判斷；沒有 Cloud Functions 定時寫入，資料庫 stage 不會因時間到自動變更，但舊連線畫面會由本機時鐘關閉，規則阻止新的讀取／作答。歷史管理會推導顯示已逾時。已取得的資料無法由伺服器回收；請勿將此當作敏感資料存取系統。

## 5. 競賽操作

### 5.1 主持人

首頁使用 Google 登入，選擇已儲存的雲端題庫並設定三種 Timeout；前台不提供題庫編輯。建立前可返回首頁，進行中可確認離開並暫停、釋放控制權。等待頁中央 QR Code 及中途加入設定維持原版。開始後控制按鈕依序為暫停／繼續（黑色膠囊）、作廢（黑色膠囊）、延長 15 秒（寶石藍）、結束作答並公布答案（紫色），間距 12 px；作答人數顯示「已作答人數：25 / 50」（數值依現況更新）。延長可累加，無須輸入或確認；作廢、返回首頁、接管使用網頁內確認視窗，錯誤使用網頁內提示；公布答案及即時排名階段亦可作廢當前題，作廢先確認，撤回本題後回到解答畫面。公布答案時正確選項與詳細解答分開，點擊展開後參賽者同步顯示。全螢幕按鈕需由主持人手動點擊，部分手機瀏覽器不支援。

一般題目解說後顯示排行榜，再進下一題；最後一題直接查看最終結果。總分、連答與題目分析三頁籤可切換，成績可匯出 Excel。回到首頁將房間改為 review，禁止新加入、作答及再次競賽；原參賽者可回顧至期限。

### 5.2 恢復與歷史管理

首頁登入後列出同帳號可恢復房間；或到 editor-preview.html 的「歷史競賽紀錄」登入搜尋房號。點恢復會開啟原房間主持人網址，保留原題目、名單與成績。舊分頁尚持有控制租約時，同 Google 帳號可確認接管，原裝置停止控制；明確離開前台會釋放控制權。作答中租約失效，參賽者端停止倒數及新作答，接管時以截止時間和租約截止較早者凍結，主持人點繼續、延長或作廢。斷線偵測有緩衝，不能保證從實際斷網瞬間暫停；若原時間已到，剩餘為 0，可在暫停時延長。回顧或已逾時／已關閉房間不可重新答題。歷史房間查詢只允許同 Google UID；關閉及刪除會避開有效的控制租約，刪除需二次確認。

### 5.3 參賽者

掃 QR Code／輸入房號和暱稱匿名加入；原瀏覽器重開可接續同 UID。排序題依序點選並提交。作答暫停不可提交；已提交答案保留。最終結果或感謝畫面可點個人回顧，篩選答對、答錯、未答、作廢及未參與題，展開詳細解答及圖片；回顧期限到停止存取。清除網站資料、換裝置或無痕瀏覽無法保證恢復匿名身分。

## 6. 題庫管理

原本編輯、排序、複製、刪除、Excel 匯入匯出、JSON 備份及預覽維持。題庫改存 Firebase banks/<主持人 UID>，Google 登入後可跨裝置取得；後台全面須登入。舊版 localStorage 題庫可由後台「匯入舊版瀏覽器題庫」匯入，不覆蓋同名雲端題庫，保留原本機資料。每次雲端儲存記錄建立與最後修改帳號、時間及修訂版號。

| Excel 欄位 | 填寫方式 |
| --- | --- |
| 題型、題目 | 原四種題型及題目文字 |
| 選項A～D | 依序，不跳欄 |
| 正確答案 | A–D；是非 A=是、B=非；排序如 B,D,A,C |
| 秒數 | 5–180 |
| 圖片網址 | HTTPS 或同網站相對路徑 |
| 答案解說 | 詳細文字 |
| 解答圖片網址 | 選填；舊版固定顯示於解說下方的圖片 |
| 格式化解答 | 選填；安全過濾後的富文字 HTML，可由編輯器自動產生。沒有此欄時使用答案解說純文字。 |

富文字工具列支援文字大小、粗體、斜體、底線、刪除線、文字顏色、醒目背景、靠左／置中／靠右、項目及編號清單、插入圖片或圖片網址、清除格式、復原／重做。先選取文字再點工具；貼上以純文字處理。圖片可插入任意段落，舊版解答圖片仍相容。解答預覽可檢查正確選項及格式。JSON 備份保留格式及內嵌圖片。

圖片上傳自動壓縮至 JPEG、最長邊 1000px。Excel 不支援內嵌圖片且單儲存格字元上限 32767；有上傳圖片請用 JSON 備份或改用 URL。勿使用未授權圖片。

## 7. 計分與排名

基本 650 分、速度最高 250 分、連答最高 100 分（自第二題起每連答加 25 分），答錯／未答 0 分並重置當前連答。速度依有效作答時間及延長後總時長計算，扣除暫停時段；已提交答案保留。中途加入前的題目為未參與，不列入該題應作答人數；作廢題不影響分數與連答。答對率＝答對／應作答人數，包含未作答者；最終平均為各有效題答對率的算術平均，排除作廢及無應答者題。總分及最長連答並列採競賽排名 1、1、3，保留首次排名藍色、寶石藍得獎姓名及全部截點並列者。

## 9. 注意事項與驗收

- 任何成功透過 Google 登入的帳號可建立自己的競賽，但不得管理其他 UID 的房間。本版沒有全站主持人白名單。參賽者匿名身分不變。
- 公布前的題目資料不包含正確選項、詳細解答或富文字欄位；依原需求即時顯示各選項作答者，因此不是防作弊模式。
- 主持人控制鎖是正常應用程式的併發保護；同一 Google UID 的主持人本來就有該房間寫入權限，並不是針對惡意主持人的防篡改伺服器。
- 房間交易由有權限的主持人裝置結算，沒有可信任後端計分服務。歷史查詢目前按 owner 查整個房間內容，房間多或圖片多會增加流量。請確認 Firebase 方案、下載量和連線配額。
- 本版不自動轉移舊匿名房間所有權；不會主動刪除資料。只支援當前題目作廢；已進入下一題或最終結果後不提供追溯作廢。
- 建議先在獨立測試專案驗證規則，再上正式環境。本次沒有實際 Firebase 憑證，尚未做線上 Auth／Rules／多人壓力測試。

### 本機驗證結果

JavaScript（含後台內嵌程式）語法、Rules JSON 格式、Excel 新欄位及 ZIP 已檢查。以 Chromium 載入後台 HTML 並內嵌本版共用資源，實測編輯、粗體、解答預覽、儲存重開及基本不安全 HTML 過濾；以 Node 模擬資料交易測試結算、同分、未參與、作廢回復、最終結果、暫停／延長／恢復。未連接真實 Firebase，未執行 Rules emulator 或 50 人壓力測試；此為部署候選版，不代表已通過線上驗收。

## 10. 歷史版本紀錄

以下依 GitHub 正式版本由新到舊排列，每版採相同欄位。歷史功能描述僅代表當時版本，現行操作以第 1–9 節為準。

### V11 特別驗收與部署限制

- 先備份並發布新版 Rules，再上傳完整網站；`admin.js`、`result-view.js` 為新增必要檔案。不要覆蓋 `config.js`。
- 登入後台後按「匯入舊版瀏覽器題庫」，或用 JSON 匯入並儲存。前台只能選擇雲端已儲存題庫。
- 控制權名義續約週期及失效皆為 3 小時；每 15 秒檢查是否進入到期前 60 秒安全窗口，避免完全同時續約／失效。短暫斷線不會立即暫停，實際斷線偵測與自動恢復需上線驗證；同帳號可確認接管。
- 保留 V10 房間 schema 10 及歷史資料，無須重新遷移 V10 房間。
- 本版完成靜態語法、固定延長及按鈕順序的程式檢查與封裝檢查；真實 Google 登入、Firebase Rules、控制權競爭、所有裝置版面及多人作答尚未驗證。
