# 知識競技場 Knowledge Arena

以 GitHub Pages 與 Firebase Realtime Database 架設的多人即時知識競賽網頁，支援主持人操作、手機掃碼加入、題庫管理及競賽成績匯出。

## 3. 部署與升級

### 3.1 既有網站升級（GitHub V6.1 → V6.2）

| 項目 | 處理方式 |
| --- | --- |
| GitHub 網頁檔案 | 上傳最新版至原部署路徑 |
| Firebase 安全規則 | 已發布上一版規則者不必再次發布 |
| Firebase 專案、資料庫及匿名登入 | 沿用現有設定 |
| config.js | 保留原檔，不覆蓋、不刪除 |
| 題庫 | 先匯出 JSON 備份 |

1. 備份現有題庫、程式及 `config.js`。
2. 將新版網頁檔案上傳至原 GitHub Pages 資料夾並 Commit。
3. 確認部署成功，重新整理電腦及手機網頁。
4. 建立全新競賽房間，依第 9 節驗收。

若從 GitHub V3.0（ChatGPT V6.0）或更早版本直接升級，請先備份舊規則，並發布本套件的 `database.rules.json`。本套件不包含空白 `config.js`。

### 3.2 首次架設（Firebase Spark 方案）

1. 前往 [Firebase Console](https://console.firebase.google.com/) 建立專案，無須啟用 Analytics。
2. 新增 Web 應用程式，複製 `config.example.js` 為 `config.js`，填入 Firebase 網頁應用程式設定。不要放入服務帳戶私鑰。
3. Authentication → Sign-in method → Anonymous，啟用匿名登入。
4. Realtime Database → Create Database，選擇地區並以鎖定模式建立；將資料庫網址填入 `databaseURL`。
5. 在 Realtime Database → Rules 貼上 `database.rules.json` 全文並發布。
6. 建立 GitHub public repository，上傳網頁檔案及已設定的 `config.js`；Settings → Pages → Deploy from a branch → main / (root) → Save。
7. Firebase Authentication → Settings → Authorized domains 加入 `帳號.github.io`（不含協定及 repository 路徑）。
8. 開啟 GitHub Pages 網址，確認連線並測試建立房間。

## 4. 系統功能與限制

| 項目 | 現行規格 |
| --- | --- |
| 參賽人數 | 房間前端限制 50 人；同時加入可能短暫超過 |
| 暱稱 | 最多 100 UTF-16 字元單位，含即時字數顯示及長度驗證 |
| 題型 | 單選題、是非題、排序題、圖片辨識題 |
| 題數與時間 | 最多 100 題，每題 5–180 秒 |
| 即時作答 | 各選項內顯示作答人數及暱稱，所有競賽角色可見 |
| 即時排行榜 | 前十名、總分、本題得分、名次變動 |
| 最終結果 | 總分及最長連答兩個分頁，各顯示前三名頒獎台及前五名列表（不足者依實際人數） |
| 成績匯出 | 全體參賽者 Excel 成績 |
| 加入與重連 | 可控制中途加入；同瀏覽器保留匿名身分時可重新連線 |
| 音效 | 預設關閉，僅主持人可啟用 |

## 5. 競賽操作

### 5.1 主持人

1. 開啟首頁，選擇「建立新競賽」並準備題庫。
2. 儲存或選擇題庫，建立競賽房間。
3. 顯示等待加入畫面的中央 QR Code，確認參賽人數。
4. 於頁首設定「允許中途加入」及「競賽中顯示 QR Code」，視需要開啟音效。
5. 按「開始競賽」。倒數結束自動公布答案，也可提前結束作答。
6. 一般題目解說後按「顯示排行榜」，再按「下一題」；最後一題解說後直接按「查看最終結果」。
7. 最終結果切換總分及最長連答排名，先匯出 Excel 成績，再按「回到首頁」關閉競賽。參賽者會收到感謝畫面，房間歷史資料保留。

### 5.2 參賽者

1. 掃描 QR Code 或在首頁輸入六位數房間代碼。
2. 輸入非空白暱稱（最多 100 字元單位），加入競賽後可於頁首確認自己的姓名。
3. 等待主持人開始；中途加入依房間目前狀態繼續。
4. 單選、是非及圖片辨識題點選即提交；排序題依序點選後按「提交順序」，提交前可重選。
5. 提交後等待公布答案，可繼續觀看即時作答名單。
6. 斷線時使用原裝置、原瀏覽器及原網址重新開啟。清除網站資料、改用無痕模式或更換裝置不保證恢復原身分。

## 6. 題庫管理

### 6.1 網頁管理

支援新增、編輯、複製、刪除、拖曳或箭頭排序、預覽、多份命名題庫、Excel 匯入匯出及 JSON 備份。題庫儲存在同網址、同瀏覽器的 localStorage，不會自動跨裝置同步。

`editor-preview.html` 可於本機開啟測試題庫編輯，不需要 Firebase；Excel 功能仍需 CDN 網路。正式建立房間請使用 `index.html`。

### 6.2 Excel 題庫格式

使用 `quiz_question_template.xlsx`，第一個工作表保留以下欄位：

| 欄位 | 填寫方式 |
| --- | --- |
| 題型 | 單選題、是非題、排序題、圖片辨識題 |
| 題目 | 題目文字 |
| 選項A、選項B、選項C、選項D | 依序填寫，不跳欄 |
| 正確答案 | 單選／圖片：A–D；是非：A=是、B=非；排序：如 B,D,A,C |
| 秒數 | 5–180 |
| 圖片網址 | 同 repository 相對路徑（如 images/01.jpg）或公開 HTTPS 網址 |
| 答案解說 | 公布答案後的說明 |

不支援 Excel 內嵌圖片。網頁上傳圖片會轉為 JPEG，最長邊縮至 1000px，單張壓縮後限制約 400KB。大型內嵌圖片請以 JSON 備份，避免 Excel 截斷。請勿使用未授權圖片或敏感個資。

## 7. 計分與排名

答對才得分，單題最高 1,000 分。

| 項目 | 比例 | 分數規則 |
| --- | --- | --- |
| 基本分數 | 65% | 650 分 |
| 速度加分 | 25% | 依剩餘時間比例計算，最高 250 分 |
| 連答加分 | 10% | 自第二題連續答對起，每多一題加 25 分，最高 100 分 |

答錯或逾時得 0 分，並重置目前連答紀錄。整場最高連答紀錄不受後續答錯影響。總分相同者並列同一名次，最長連答題數相同者也並列同一名次，不以其他指標打破平手。採競賽排名，例如 1、1、3、4。其他指標僅供並列者穩定排列順序，不影響名次。前十名、前五名與前三名的截點包含所有同名次者，因此顯示人數可能超過原定數量。最長連答排行榜不列入零連答者。首次排名不比較升降；後續依上一次已結算名次比較。

## 9. 注意事項與驗收

- 活動中請保留主持人瀏覽器並僅開一個主持人控制頁；若結算中斷，使用原瀏覽器重開主持人網址並繼續結算。
- 匿名使用者可讀取已知房號的公開狀態、暱稱、分數及目前題目的作答資料；未作答者也可看到其他人的選項。本系統不適合高風險考試或嚴格防作弊用途。
- 題庫及未公布的正確答案由私有題庫保存。房間資料可於活動後由管理者在 Firebase Data 頁刪除。
- Firebase SDK、SheetJS、QRCode.js 透過 CDN 載入，須有網路；活動前確認連線及圖片正常。
- 既有文件記載 Spark 同時連線上限為 100；實際使用前請確認 Firebase 方案配額。50 人為設計目標，不代表已通過壓力測試。

### 驗收清單

- [ ] 主持人等待頁：無人時隱藏名單，有人時靠左折行，開始按鈕可操作。
- [ ] 競賽中 QR Code：位置、尺寸、掃描及中途加入正常。
- [ ] 手機及電腦：四種題型、即時作答、答案解說、排行榜及長暱稱正常。
- [ ] 計分、逾時、連答、名次變動及斷線重連正常。
- [ ] 首次排名、中途加入、參賽者姓名及最後一題直接進入最終結果正常。
- [ ] 最終兩種排名、Excel 匯出及關閉房間正常。
- [ ] 逐步完成兩台裝置、10 人及 50 人連線測試。

V9.2 已執行 JavaScript 語法及首次排名、最後一題流程邏輯測試；尚未完成實際瀏覽器、手機掃碼及 Firebase 多人同步驗收。升級後請建立新房間，避免沿用舊排名資料。
